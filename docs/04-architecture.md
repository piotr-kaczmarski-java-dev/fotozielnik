## Backend structure _(template baseline)_

Package by feature: `<base>.<feature>` holds everything for one area of the domain
(`<base>` = `basePackage` in `backend/build.gradle.kts`).

```
<base>
  Application              entry point
  config/                  cross-cutting Spring config (SecurityConfig, OpenApiConfig)
  shared/                  small shared types (NotFoundException), shared/web (ApiExceptionHandler)
  system/                  template smoke endpoint (/api/public/info)
  <feature>/               e.g. orders/
    OrderController        HTTP only: validate input, call service, map to response DTO
    OrderService           transactions + business rules (@Transactional here, not in controllers)
    Order, OrderRepository JPA entity + Spring Data repository
    CreateOrderRequest,    request/response DTOs as records; entities never leave the service layer
    OrderResponse
```

- Types are **package-private by default**; make a type public only when another feature needs it.
  Features talk to each other through services, never through another feature's repository.
- A feature that grows gets sub-packages (`orders/api`, `orders/domain`) - not before.
- Constructor injection only. Configuration via `@ConfigurationProperties` records, not scattered `@Value`.

## Data _(template baseline)_

- PostgreSQL. **Flyway owns the schema** (`backend/src/main/resources/db/migration`); Hibernate only
  validates it (`ddl-auto: validate`). Committed migrations are immutable.
- `spring.jpa.open-in-view: false`: load what a response needs inside the service (fetch joins, DTO projections).
- Primary keys, auditing columns, soft delete: _(project-specific - decide in the first feature, ADR)_.

## API _(template baseline)_

- JSON over HTTP under `/api/...`; public routes under `/api/public/...`.
- Errors are RFC 9457 `ProblemDetail` (`shared/web/ApiExceptionHandler`); validation errors included.
- Requests validated with Jakarta Validation on request records (`@Valid @RequestBody`).
- The OpenAPI spec is generated by springdoc (dev only; off in the `prod` profile). Non-null by default:
  properties are `required` unless `@Nullable` (`config/OpenApiConfig`).
- The frontend's types are **generated** from that spec (`npm run api:types` -> `src/api/schema.gen.ts`, ADR-0004).

## Security _(template baseline + project-specific)_

- Deny by default (`config/SecurityConfig`): every new public route is listed there deliberately.
- Unauthenticated API calls get 401 (no login redirects).
- Stateless, CSRF off - valid only while there are no auth cookies.
- **Authentication mechanism:** _(project-specific - decided at kickoff, ADR required; revisit CSRF then)_.

## Testing strategy _(template baseline)_

| Level | Tool | Where | Docker |
|---|---|---|---|
| Unit | JUnit 5 + AssertJ / Vitest | `backend/src/test/...*Test`, `frontend/src/**/*.test.tsx` | no |
| Web slice | `@WebMvcTest` + MockMvc (import `SecurityConfig`) | `*ControllerTest` | no |
| Integration | `@SpringBootTest` + Testcontainers Postgres | `*IT` | yes |
| End to end | Playwright against the running stack | `frontend/e2e/*.spec.ts` | yes |
| Visual check | `tools/look.sh` screenshot + console/network errors | `captures/` | yes |

- Every feature: unit tests for rules, a slice test per controller, at least one `*IT` through the database.
- Every critical user flow: one e2e test.
- Static analysis on every compile: Error Prone + NullAway (errors), Spotless format (ADR-0003).
